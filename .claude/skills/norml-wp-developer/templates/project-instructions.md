# Project operating instructions

Merge these rules into the existing instruction router; do not replace unrelated rules.

Before every change, read the relevant current architecture, design, components, integrations,
capabilities and release documents. Verify the actual files and current Git state.
Reuse existing components and styles. Keep to the requested scope and preserve unrelated work.
Check the implemented result against the project’s rules and real preview behavior.
Update affected documentation after the implementation changes.
Follow the documented Git, publishing, approval and recovery process.
Never place credentials, customer records, database dumps or backups into committed context.
If required facts or checks are missing, state the exact blocker instead of guessing or claiming success.
